# 画面2：お店詳細画面

## 1. レイアウト説明

- 画面最上部に、iOSのセーフエリアを考慮したナビゲーションバーを配置する。
  - 左上に戻るボタン「＜ お店メモ」を置く。タップすると画面1「お店一覧画面」へ戻る。
  - 中央に画面タイトル「お店詳細」を表示する。
  - 右上にテキストボタン「編集」を置く。タップすると、現在のお店の情報を読み込んだ画面3「お店登録／編集画面」へ移動する。
- ナビゲーションバーの下に、選択したお店の店名を大きめ・太字で表示する。長い店名は省略せず、複数行で表示できるようにする。
- 店名の下にセクション見出し「メモ」を置き、その下にメモ本文を自由記述の1つのテキストとして表示する。
  - メモ本文は入力欄のように見せず、閲覧しやすい通常の本文として表示する。
  - 本文が画面に収まらない場合は、画面全体を縦にスクロールできるようにする。
- メモ本文の下に、補助情報として最終更新日時を小さく表示する。登録日時はMVPでは画面に出さず、情報量を抑える。
- この画面には削除ボタンを置かない。削除は、右上の「編集」から進んだ画面3内で行う。

## 3. 画面遷移

- **この画面への入口**
  - 画面1「お店一覧画面」で、お店の行をタップするとこの画面へ移動する。
  - タップしたお店の店名・メモ本文・更新日時を表示する。
- **この画面からの移動**
  - 左上の「＜ お店メモ」をタップすると、画面1「お店一覧画面」へ戻る。
  - iOSの一般的な戻る操作として、画面左端から右方向へのスワイプでも一覧へ戻れるようにする。
  - 右上の「編集」をタップすると、画面3「お店登録／編集画面」を編集モードで開く。
  - 編集画面で保存した場合はこの画面へ戻り、更新後の店名・メモ本文・更新日時を表示する。
  - 編集画面でお店を削除した場合は、表示対象がなくなるため、この画面には戻らず画面1へ移動する。

## 4. UI 注意点

- 店名やメモが長い場合でも内容を失わないよう、画面全体をスクロール可能にし、店名は複数行、メモ本文は全文表示とする。
- 改行や空行を含むメモは、入力時の文章構造を保って表示する。カスタマイズ内容や感想を別項目に分割しない。
- メモが空文字または空白のみの場合は、空の領域だけを見せず「メモはまだありません」と案内する。
- 更新日時は端末のローカル日時で、読みやすい表記に統一する。相対表記だけにはせず、日付を確認できるようにする。
- 「編集」は文字だけでなく十分なタップ領域を確保する。戻る・編集ともに、VoiceOverで意味が分かるラベルを設定する。
- PWAでも画面上の戻るボタンを常に表示し、ブラウザやホーム画面起動時の操作差に依存しない。履歴操作で一覧へ戻ったときも、検索語やスクロール位置をできるだけ維持する。
- 写真・評価・ジャンル・地図など、MVP対象外の情報を置くための空欄やアイコンは設けない。
