# 画面3：お店登録／編集画面

## 1. レイアウト説明

- 画面最上部に、iOSのセーフエリアを考慮したナビゲーションバーを配置する。
  - 左上に戻るボタンを置く。登録モードでは「＜ お店メモ」、編集モードでは「＜ 詳細」と表示する。
  - 中央の画面タイトルは、登録モードでは「お店を追加」、編集モードでは「お店を編集」とする。
  - 右上に主要操作の「保存」ボタンを置く。店名が未入力、または空白のみの場合は無効状態にする。
- ナビゲーションバーの下にフォームを配置する。
  1. ラベル「店名」と、1行のテキスト入力欄を置く。登録モードでは「例：カフェ 青空」をプレースホルダーとして表示し、編集モードでは現在の店名を初期表示する。
  2. ラベル「メモ」と、複数行入力できる大きなテキストエリアを置く。メモは項目分けせず、自由記述の1つのテキストとして編集する。
  3. テキストエリアには「例：オーツミルクに変更。シロップは半分がちょうどよかった」のような、用途が分かるプレースホルダーを表示する。
  4. 入力欄の下に「注文内容、カスタマイズ、量の感想などを自由に記録できます」という短い補足を置く。
- 編集モードの場合のみ、フォームの下部に区切りを設け、赤色の「このお店を削除」ボタンを配置する。
  - 削除は保存とは異なる破壊的操作なので、右上には置かない。
  - 登録モードでは削除ボタンを表示しない。
- キーボード表示時にも編集中の項目や保存操作へ到達できるよう、フォーム全体を縦スクロール可能にする。

## 3. 画面遷移

- **登録モードへの入口**
  - 画面1「お店一覧画面」右上の「＋」をタップすると、空の入力フォームを登録モードで開く。
- **登録モードからの移動**
  - 右上の「保存」をタップすると、新しいお店とメモを端末内へ保存し、画面1へ戻る。保存したお店は更新日時の新しい順で一覧の先頭に表示する。
  - 左上の「＜ お店メモ」をタップすると、保存せず画面1へ戻る。入力済みの内容がある場合は、戻る前に変更破棄の確認を表示する。
- **編集モードへの入口**
  - 画面2「お店詳細画面」右上の「編集」をタップすると、既存の店名とメモを入力欄に表示した編集モードで開く。
- **編集モードからの移動**
  - 右上の「保存」をタップすると同じお店のデータを上書きし、更新日時を更新して画面2へ戻る。
  - 左上の「＜ 詳細」をタップすると、保存せず画面2へ戻る。変更済みの場合は、戻る前に変更破棄の確認を表示する。
  - 「このお店を削除」をタップすると確認ダイアログを表示する。「削除する」で削除を確定し、画面1へ移動する。「キャンセル」では削除せず編集画面に戻る。
- iOSの画面左端から右方向への戻るスワイプを許可する場合も、未保存の変更があるときは同じ変更破棄確認を行う。

## 4. UI 注意点

- 店名は必須とする。前後の空白を除去した結果が空の場合は保存できないようにし、入力欄の近くに「店名を入力してください」とエラーを表示する。
- メモは任意入力とし、空でもお店を保存できる。空白のみのメモは空文字として扱い、詳細画面では空状態を表示する。
- 入力内容に変更がない場合、編集モードの「保存」は無効にしてよい。保存処理中は二重登録を防ぐため、保存ボタンを一時的に無効にする。
- 未保存の入力がある状態で戻ろうとした場合は、「変更を破棄しますか？」という確認を挟み、「変更を破棄」と「編集を続ける」を選べるようにする。
- 削除確認では対象の店名と、メモも一緒に削除されることを明記する。「削除する」は赤色の破壊的ボタン、「キャンセル」は通常のボタンとして表示する。
- 削除完了後は、存在しなくなった詳細画面へ戻さず一覧画面へ移動する。検索結果から編集を開始した場合も同様とする。
- メモは自由記述の単一フィールドを維持し、カスタマイズ・量・感想などの入力欄を追加しない。改行を保存し、再編集時に同じ形で復元する。
- キーボードで現在の入力欄や削除ボタンが隠れないよう、スクロールとキーボード回避を実装する。店名入力のReturnキーは次のメモ欄へ移動させると入力しやすい。
- 長文入力、文字サイズの拡大、VoiceOverを考慮し、固定高さだけに依存しない。各ボタンには十分なタップ領域と明確なアクセシビリティラベルを設定する。
- PWAでは画面遷移をブラウザ履歴と同期させ、表示上の戻るボタンとOS・ブラウザの戻る操作で結果が食い違わないようにする。
