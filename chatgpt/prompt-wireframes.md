=== ここから貼り付け ===

あなたはモバイルアプリの UI/UX 設計を手伝うアシスタントです。
これから渡す「要件定義書」に基づいて、**個人向けの飲食店メモアプリ「お店メモ」**の
ワイヤーフレーム（画面イメージ図）を、テキストベースで作成してください。

このアプリは既に画面1「お店一覧画面」のワイヤーフレームが作成済みです。
今回お願いしたいのは、**まだ未作成の以下2画面**です。

- **画面2: お店詳細画面**
- **画面3: お店登録／編集画面**

## 各画面について、次の4項目をこの順で出力してください

1. **レイアウト説明** — 画面上に何が、どの位置に、どういう役割で配置されるかを文章で
2. **枠線図** — テキスト（罫線文字）だけで描いた画面のワイヤー。iPhone の縦画面を想定
3. **画面遷移** — この画面にどこから来て、どのボタンでどこへ行くか
4. **UI 注意点** — 実装時に気をつけるべき点（空状態、バリデーション、確認ダイアログ、削除操作など）

## 守ってほしい制約

- **アプリ名は「お店メモ」で統一**すること（「ご飯メモ」など別名は使わない）
- iOS の一般的な作法に合わせること（画面上部のナビゲーションバー、左上に戻るボタン、右上に「編集」ボタンなど）
- 画面1と**粒度・スタイルを揃える**こと（画面1も上記4項目構成で作られている）
- 要件定義書の「やらないこと」に含まれる機能（写真・評価★・ジャンル・地図・通知・同期）は**画面に出さない**こと
- データ構造は「お店1件がメモ1件を持つ（1対1）」。メモは項目分けせず**自由記述の1つのテキスト**として扱うこと
- 枠線図に、アプリと無関係な要素（ツールの「タスクに追加」帯など）を**混入させないこと**
- 削除操作は、画面3（編集）内に「削除」導線を置くこと。削除時は確認ダイアログを挟むこと

## 出力フォーマット（そのまま2ファイルに保存できる形で）

出力は、下記のように **2つのファイルに切り分けられる形**で返してください。
各ファイルは `----- FILE: ファイル名 -----` という行で始め、そのすぐ下から中身（Markdown）を書きます。

```
----- FILE: screen2-detail.md -----
# 画面2: お店詳細画面
（ここに 1.レイアウト説明 / 2.枠線図 / 3.画面遷移 / 4.UI注意点 を書く）

----- FILE: screen3-edit.md -----
# 画面3: お店登録／編集画面
（ここに 1.レイアウト説明 / 2.枠線図 / 3.画面遷移 / 4.UI注意点 を書く）
```

- Markdown で、見出しと箇条書きを使って読みやすく
- 枠線図は ``` コードブロックで囲む
- 余計な前置き・後書きは書かず、上記2ファイルぶんの内容だけを返すこと
